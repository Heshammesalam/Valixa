# Valixa 1.0.0-rc.2 — prepared, not published

All eleven public unscoped packages follow the fixed candidate version train at
**1.0.0-rc.2**, tag **next**. Stable 1.0.0 is not being published.

## Changes

- Add optional `valixa/standard` with Standard Schema v1 field/form adapters and
  explicit typed output parsing. Actual Zod, Yup and Valibot providers are tested.
- Protect caller/form input from provider mutation; preserve cancellation, timeouts,
  stale-result handling and existing input types during validation.
- Map literal/nested/collection/root provider issues through the actual blueprint.
- Add shared purchase-order pilots for React/MUI and Vue/Vuetify and a pinned Nuxt
  SSR/request-isolation/hydration fixture, plus a reproducible VeeValidate comparison.
- Patch an actual prototype-poisoning issue in the private Nuxt build dependency
  with retained upstream license/hashes and regression tests; no advisory is ignored.
- Pin isolated consumers to the lockfile-tested Rollup version and await Vue DOM
  reconciliation when checking reordered row identities across browsers.

Existing entry points and 31 declaration baselines are unchanged. Core still has
no runtime dependencies. All internal packed ranges match the new candidate.
Private examples and the local build-tool patch are not npm release packages.

## Limits and release gate

Read [Standard Schema contracts](../standard-schema.md), [Nuxt scope](../nuxt.md),
[development evidence](../development-upgrade.md) and [comparison limits](../vee-comparison.md).
The pilots use simulated APIs; independent production adoption is not established.
Collection schema issues aggregate on the collection, and provider-internal work
cannot be forcibly cancelled by the generic Standard Schema contract.

Candidate verification now requires fifteen shared gates, including production
Nuxt build/type/browser checks, isolated package consumers and both performance
investigations. Verification and the protected publisher use the same gate list.

No npm upload, GitHub release or publishing tag is authorized by preparation alone.
Present exact inventory, hashes, actual results and publication method before the
final immutable-release approval. Do not claim publication until registry versions,
tags and downloaded SHA-512 values are confirmed.
